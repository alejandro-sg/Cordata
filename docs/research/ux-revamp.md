# Cordata UX Research & 2028 Interface Architecture

**Bottom line (the one bet in three sentences):**
Replace the scrolling chat transcript and bottom prompt box with a **Proof-First Change Sheet** where the primary artifact is an executable contract (`done when <check>`) paired with a semantic delta map and verification ledger, pushing raw agent dialogue and tool logs into an on-demand flight-recorder scrub bar. As agent runs stretch from seconds to hours across parallel APFS sandboxes, a chronological stream of prose and tool calls actively degrades situation awareness (Endsley, 1995) and induces permission habituation (Akhawe & Felt, 2013). Centering the desk on *verified state transitions and invariant diffs* lets one developer supervise twenty concurrent runs by exception without losing causal ownership of what ships.

### 1.2 First Principles (Without Assuming a Conversation)

Chat interfaces exist because early LLMs were stateless text-completion endpoints. When you remove the assumption of a back-and-forth dialogue, the fundamental units of agentic software engineering change:

| Dimension | Chat Era (2023–2026) | Supervisory Era (2028 First Principles) | Why Chat Breaks |
|---|---|---|---|
| **Unit of Work** | **A Prompt / Turn**: A natural-language request followed by streamed prose and tool calls ([`Message::User`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-view/src/desk.rs#L23), [`Message::Agent`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-view/src/desk.rs#L371)). | **A Verified State Transition (Contract $\rightarrow$ Patch + Proof)**: An explicit specification of *intent*, *write scope*, and *falsifiable check* ([`check_command`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-view/src/desk.rs#L287-L313)) that transforms repository state $S_0 \rightarrow S_1$. | A prompt has no completion semantics; prose can claim success while breaking invariants. Turns are arbitrary slices of model context, not software milestones. |
| **Unit of Attention** | **The Token Stream / Scroll Position**: Watching words appear at 80 tok/s or scrolling a vertical log to see what happened ([`transcript.rs`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/transcript.rs)). | **The Decision Boundary (Gate or Anomaly)**: A moment where an invariant is threatened, an ambiguity cannot be resolved from the repo, or a proof has a coverage gap. | Human reading speed (~250 wpm) cannot scale to 20 parallel agents generating 2,000 tok/s combined. Watching normal execution wastes scarce supervisory attention. |
| **Unit of Trust** | **Rhetorical Plausibility & Tool Approval**: Believing the agent's explanation and clicking `Allow` on individual shell commands ([`approval_card`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/conversation.rs#L295-L439)). | **Deterministic Blast Radius & Independent Falsification**: Physical sandbox boundaries (Seatbelt + APFS scope), automated test/coverage delta, and adversarial cross-family audit ([`orchestrator.md`](file:///Users/asierra-llm-mbp/Development/Cordata/docs/orchestrator.md#L58-L62)). | Models are persuasive sycophants; humans habituate to command prompts within minutes. Trust must attach to *what cannot happen* (sandbox) and *what was proven* (check), never to what the agent *said*. |

### 1.3 Borrowing from High-Consequence Supervisory Domains

| Source Field | What to Take into Cordata | What NOT to Take (and Why) |
|---|---|---|
| **1. Air Traffic Control (Flight Progress Strips & Handoffs)** | Physical/spatial **Flight Strips** per job that encode callsign (brief), altitude/clearance (write scope + sandbox tier), and next waypoint (check status) in fixed columns; physical **bay sorting** (*Active*, *Needs Clearance*, *Landed*) and explicit **Handoff Packets** ([`handoff_packets`](file:///Users/asierra-llm-mbp/Development/Cordata/tui/crates/cordata-ledger/src/lib.rs#L320-L330)) when switching model pools. | Continuous real-time radar vectoring. Software in an APFS sandbox cannot collide mid-air in 10 seconds; constant spatial motion creates visual fatigue without actionable urgency. |
| **2. Surgical Checklists & Time-Outs (WHO / Gawande)** | **Challenge-and-Response Time-Outs** before irreversible actions (network egress, schema changes, deleting tests): the operator must identify *what* is being altered (e.g., clicking the target path/flag) rather than pressing a reflex `↵` key. | Mandatory multi-person verbal sign-offs on routine, reversible actions (which [`auto::judge`](file:///Users/asierra-llm-mbp/Development/Cordata/docs/auto-mode.md#L80) already rightly automates inside the sandbox). |
| **3. Film Editing Timelines & Dailies (NLEs)** | **Non-destructive Playhead Scrubbing** across checkpoints, **J-K-L shuttle speed** through a turn's state mutations, and **Dailies Binning** (reviewing only the "selects"—the final diffs and test outputs—while hiding raw camera setup/read calls). | Frame-accurate multi-track keyframe curves. Code changes are discrete AST/hunk mutations, not continuous 60fps media streams. |
| **4. Music Production (DAWs: Tracks, Takes, Comping)** | **Take Lanes & Comping**: running 2–3 cheap parallel workers on a tricky module and swiping across hunks from Take A (cleaner struct) and Take B (better edge-case tests) in [`review.rs`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/review.rs) to assemble a composite patch. | Mixing buses, continuous faders, and real-time effects chains, which have no analogue in discrete compilation. |
| **5. Newsroom Editors & Copy Desks** | **Inverted Pyramid Structure** (lead with the Receipt and headline change; bury tool traces below the fold), **graf-by-graf kill/stet** markup, and **fact-checker provenance** (every claim in a research brief must link to a verified `path:line` quote, as [`research.rs`](file:///Users/asierra-llm-mbp/Development/Cordata/docs/orchestrator.md#L46-L48) enforces). | Strict hierarchical role handoffs for trivial 1-line fixes where a single pass suffices. |
| **6. Chess Engine Analysis Lines (Centipawn Eval & PV)** | **Principal Variation (PV) Preview**: showing the *consequence line* of a decision at a gate ("If Allowed $\rightarrow$ modifies 3 files, runs `cargo test`; If Denied $\rightarrow$ falls back to local mock"), and **Blunder Detection** (highlighting the exact turn on the [`tape`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/desk.rs#L137) where test pass rate dropped). | A single scalar "eval bar" (e.g., `+2.4`) for code quality—software correctness is multi-dimensional and non-zero-sum. |
| **7. Logistics Control Towers** | **Management by Exception**: 95% of shipments (threads) moving on schedule are gray/quiet; only stalled runs (loop guard near threshold, context $>80\%$, blocked gate) surface to the top of the board with root-cause tags. | Geographic map projections and decorative supply-chain animations (which is why [`studio.rs`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/studio.rs#L149-L182)'s pulsing Bézier beads and grids must be discarded). |
| **8. Legal Redlining & Contract Comparison** | **Semantic Clause Diffing** against a baseline contract (highlighting where a diff touches security-critical clauses like `unsafe`, `.env`, auth, or public trait signatures differently from internal formatting) and **Obligation Tracking** (mapping every clause in the Brief to the hunk/test that fulfills it). | Inline character-by-character strikethroughs inside prose documents, which become unreadable on code refactors. |
| **9. Pilots' Glass Cockpits & Airbus Dark Cockpit Philosophy** | **Dark Cockpit Principle**: normal = quiet, monochrome, unlit; colour ([`attention` ochre `#E2A640` and `danger` `#E5584E`](file:///Users/asierra-llm-mbp/Development/Cordata/app/assets/brand/README.md#L38-L40)) illuminates *only* when human intervention is required. Plus **EICAS Alert Hierarchy** (Advisory vs. Caution vs. Warning). | 40 simultaneous numeric gauges. A developer cannot monitor 20 live token-per-second counters simultaneously. |

### 1.4 Three Thought Experiments

#### Thought Experiment 1: Delete the Transcript (`transcript.rs`)
If we delete the scrolling message list in [`transcript.rs`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/transcript.rs) tomorrow, what breaks, and what replaces each job it secretly did?

1. **Job 1: Remembering what I asked and how I steered the agent.**
   - *Replacement*: **The Living Contract (Brief + Amendments)**. The [`brief`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-view/src/desk.rs#L21-L31) header expands from a static first-prompt string into a structured specification block with pinned steering amendments (e.g., `Amendment #2: keep public signature of desk::places unchanged`).
2. **Job 2: Seeing whether the agent is alive, stuck in a loop, or making progress.**
   - *Replacement*: **The Live Line + Places Touch Map + Checkpoint Tape**. The header's 1px [`live_line`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/conversation.rs#L70-L98) and the [`places_margin`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/desk.rs#L192-L303) show real-time file touches (`●` working, `+` edited, `✕` failed) and check runs directly on the repository's component tree.
3. **Job 3: Understanding *why* the agent chose approach A over B.**
   - *Replacement*: **Hunk-Anchored Rationale Annotations**. Instead of a 400-word essay in a chat scroll, the agent attaches 1–2 sentence rationale notes directly to the changed hunks in [`review.rs`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/review.rs) and to its Receipt.
4. **Job 4: Answering the agent's questions or approving a risky command.**
   - *Replacement*: **The Gate Slot**. The [`approval_card`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/conversation.rs#L295-L439) mounts directly under the Brief as a first-class decision surface with full diff/blast-radius context, disappearing once resolved.
5. **Job 5: Forensic debugging when a run goes off the rails.**
   - *Replacement*: **The Flight Recorder Inspector**. Clicking any stop on the [`tape`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/desk.rs#L137-L189) opens a compact, filterable forensic drawer for *that turn only* (tool calls, exit codes, raw stderr), never forcing the user to scroll through 50 earlier turns.

#### Thought Experiment 2: A Day with 20 Agents Running at Once
When 20 agents run in parallel across worktrees and APFS sandboxes, clicking through 20 tabs in a 232px sidebar ([`sidebar.rs`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/sidebar.rs)) causes catastrophic **change blindness** and **working-memory thrash**. What does the developer look at instead?
- **The Triage Rack & Territory Collision Matrix**: The center view defaults to a **Multi-Desk Triage Board** sorted strictly by human-action priority:
  1. **Blocked at Gate (`C█` Ochre)**: Sorted by how many downstream wave steps depend on this decision. Batch-similar gates (e.g., 3 workers asking to fetch from `crates.io`) group into a single **Batch Gate** card.
  2. **Ready for Harvest (`◯` Done + Check Passed)**: Grouped into a **Dailies Review Queue** where the developer steps through diffs with `J`/`K`, keeping or reverting whole runs in one keystroke.
  3. **Drifting / Anomalous (`C▚` Danger)**: Any worker where [`LoopGuard`](file:///Users/asierra-llm-mbp/Development/Cordata/tui/crates/acp-core/src/native/engine.rs#L11) triggered a warning, a check failed twice in a row, or two workers touched overlapping module boundaries.
  4. **Cruising (`(█` Signal, collapsed to 1 summary line)**: 14 workers cruising inside their sandboxes fold into a single quiet status strip (`14 cruising · 0 collisions · $1.12/hr`), obeying the Dark Cockpit principle.

#### Thought Experiment 3: An Agent That Is Right 99% of the Time
By Bainbridge's **Ironies of Automation** (1983) and Parasuraman & Manzey's **Automation Bias** (2010), an agent that succeeds 99% of the time is *more dangerous* to human vigilance than one that succeeds 70% of the time. At 99% reliability, the human stops reading diffs and rubber-stamps every gate (`↵`) and every PR. How does the UI keep the human alert for the 1%?
1. **Asymmetric Friction at the Gate (De-habituation)**: Remove the muscle-memory `↵` shortcut on high-consequence gates (network POSTs, destructive git ops, edits to `.cargo/config.toml` or build scripts). Require **Semantic Target Selection**: the user must click or type the 2-letter token of the *resource being risked* (e.g., clicking the external hostname `api.example.com` or the `--force` flag in the command block) to unlock execution.
2. **Automated Counter-Evidence (The Goldfish Strip)**: Whenever a turn finishes, the UI does not lead with the agent's self-reported success summary. It leads with **Falsification Signals**:
   - *Uncovered New Lines*: Lines added in the diff that were *not* executed by `check_command`.
   - *Test-Weakening Detector*: Any deletion or assertion removal inside `#[cfg(test)]` or `tests/` is highlighted at the top of the Receipt in [`attention` ochre](file:///Users/asierra-llm-mbp/Development/Cordata/app/assets/brand/README.md#L38), even if `cargo test` passed!
   - *Scope Creep Flag*: Any edit to a file not mentioned in the Brief or outside the primary crate area.

### 2.2 Phase 2 Judge Scoring Matrix

> **[MODE: JUDGE]** — *Evidence-driven evaluation under Rust/GPUI constraints, local SQLite ledger (`~/.cordata/state.db`) & session telemetry (`cordata_view::telemetry`), and Cordata's brand rules (`app/assets/brand/README.md`).*

**Scoring Legend**:
- **User-Job Fit**: `1` (marginal) to `5` (core supervisory bottleneck).
- **Trust Calibration** (Lee & See, 2004): `+2` (aligns perceived trust with actual capability) to `-2` (induces over-trust or cynicism).
- **Approval Fatigue** (Akhawe & Felt, 2013): `+2` (sharply reduces reflex clicking / alert noise) to `-2` (increases interruption load).
- **Situation Awareness** (Endsley, 1995 — Level 1 Perception, Level 2 Comprehension, Level 3 Projection): `+2` (supports L2/L3 projection) to `-1` (clutters L1).
- **Effort in Rust/GPUI**: `S` (< 3 days, pure `cordata-view` + minor GPUI layout), `M` (1–2 weeks, new state/events across `acp-core` and `cordata-app`), `L` (3–6 weeks, multi-crate architecture).
- **Evidence Strength**: **Strong** (direct HCI empirical replication), **Moderate** (established HCI theory applied to coding), **Borrowed** (validated in aviation/medicine/finance, transferred to software), **Hypothesis** (`test:` speculative design requiring validation).

### 4.2 Ten Required HCI Dimensions (Judge Synthesis)

1. **Mental Models (Norman, 2013; Kulesza et al., 2015)**
   - *Failure Today*: [`studio.rs`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/studio.rs) projects a fictional 7-node swarm ("Architect", "Worker 1", "Worker 2", "Goldfish") during a single-agent chat turn, while the actual [`cordata-orchestrator`](file:///Users/asierra-llm-mbp/Development/Cordata/docs/orchestrator.md) runs in the CLI (`cordata run`) completely disconnected from the desk UI.
   - *Fix*: Unify the mental model around **One Desk = One Contract**. Whether backed by a single `acp-core` loop or a multi-wave `cordata-orchestrator` run in `state.db`, the desk shows only *real* entities: the Contract (`Brief`), the Sandbox Boundary (`Gate`), the Touched Territory (`Places`), and the Verification (`Receipt`). When an orchestrator wave actually spawns 3 parallel workers, `Tape` branches into 3 parallel lanes (`second voice` lavender `#A096E6` for delegated workers, [`brand/README.md#L39`](file:///Users/asierra-llm-mbp/Development/Cordata/app/assets/brand/README.md#L39)); when 1 agent runs, 1 line is drawn.
2. **Capability Discovery (Amershi et al., 2019 — G1, G2)**
   - *Mechanism*: Cordata's [`empty_state()`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/conversation.rs#L165-L293) already sets a strong baseline by naming the project's exact `check_command` (*"Here, done means `make app-test` passes; you decide at every gate"*). Extend this by replacing static starter strings when uncommitted changes or failing tests exist with **State-Derived Starters** (e.g., if the last terminal command in `DockTab::Terminal` exited non-zero, offer `→ Fix the failing command in Terminal (exit 101)`).
3. **Trust Calibration (Lee & See, 2004)**
   - *Mechanism*: Trust must be calibrated per-turn, not globally. **I1 (Falsification-First Receipt)** and **I5 (Blast-Radius Tags)** ensure that a turn touching `sandbox.rs` with 0 new tests looks visually distinct (`attention` ochre warning) from a turn touching `docs/app.md` with passing checks (`signal` viridian), preventing uniform over-trust.
4. **Automation Bias & Complacency (Parasuraman & Manzey, 2010; Buçinca et al., 2021)**
   - *Mechanism*: Cognitive forcing functions (**S1 Challenge-Response Gate** and **R5 Goldfish Counter-Audit**) interrupt system-1 heuristic processing at the two highest-risk moments: approving an out-of-sandbox command and accepting a completed diff.
5. **Error Recovery & Undo (Amershi et al., 2019 — G8; Norman, 2013)**
   - *Mechanism*: Today, [`approval_card`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/conversation.rs#L318) promises *"An edit: you can revert it afterwards in Review"*, but reverting a multi-file turn 4 turns later requires hunting through working-tree git diffs. **I3 (Checkpoint Scrubber & Turn Forking)** makes every turn stop on the [`tape`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/desk.rs#L137) an atomic undo/fork point backed by git tree snapshots.
6. **Uncertainty & Verification Status**
   - *Mechanism*: Distinguish four epistemic states in [`CheckState`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-view/src/desk.rs#L211-L216):
     1. `Verified` (Check ran, exited 0, no test assertions removed).
     2. `Weakened` (Check exited 0, but test assertions were deleted or `#[ignore]` added — **I1**).
     3. `Unchecked` (`r.files > 0` and check has not run since the last edit — already shown as `"not checked yet"` in [`workspace/desk.rs#L346`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/desk.rs#L346)).
     4. `Failed` (Check exited non-zero or output matched [`says_failed()`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-view/src/desk.rs#L278)).
7. **Human Agency & Supervisory Control (Parasuraman, Sheridan & Wickens, 2000)**
   - *Mechanism*: In `auto` mode, the developer moves from Level 2 automation (approving every tool call) to Level 6/7 (supervisory control by exception and contract scope). Agency is preserved because the human owns the **Contract Boundaries** (write scope + `done when` check) and every hunk's final staging (`keep`/`revert` in [`review.rs`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/review.rs)).
8. **Latency & Long Runs**
   - *Mechanism*: For runs lasting 30 seconds to 2 hours, token-speed spinners create anxiety. ## 6. Validation Plan (4 Hermetic & Dogfood Experiments)

All four experiments are designed for a **solo developer plus 3–5 experienced dogfood testers** over 2–4 weeks, requiring zero cloud telemetry: every metric is queried locally from `~/.cordata/state.db` ([`cordata-ledger`](file:///Users/asierra-llm-mbp/Development/Cordata/tui/crates/cordata-ledger/src/lib.rs#L341-L355)) and `~/.cordata/sessions/<project>/*.json`.

### Experiment 1 (Early Kill Test for Radical Bet R1): Change-Sheet vs. Transcript-First Comprehension
- **Hypothesis (`test:`)**: Developers reviewing a completed multi-file agent turn on the **Proof-First Change Sheet (R1)** (Contract + Falsification Receipt + Grouped Hunks, with chat log collapsed into the Tape drawer) will identify seeded bugs faster and revert bad hunks more accurately than in the scrolling Transcript view, *without* reopening the full raw transcript on $>80\%$ of code-editing turns.
- **Kill Criterion (What kills R1 early)**: If developers click to expand the raw chronological transcript on **$>40\%$ of code-editing turns**, or report feeling disoriented about agent intent, **kill full transcript replacement** and keep the Change Sheet as a synchronized split/toggle view rather than replacing the default column.
- **Method & Sample**: Within-subjects crossover over 10 real development days ($N = 4$ developers, ~80 turns total; 5 days default `CenterView::ChangeSheet`, 5 days default `Transcript`), plus 6 seeded "fault turns" (3 where the agent's prose claims a fix that the diff misses, 3 where a test assertion is weakened).
- **Success Criterion**:
  1. Raw transcript drawer opened on $<20\%$ of turns where `r.files > 0`.
  2. $100\%$ detection of the 6 seeded fault turns (vs. baseline $\le 50\%$ in transcript-first).
- **Local Ledger SQL Query (`~/.cordata/state.db`)**:
  ```sql
  SELECT
    json_extract(payload, '$.default_view') AS view_mode,
    COUNT(*) AS total_code_turns,
    AVG(CAST(json_extract(payload, '$.transcript_drawer_opened') AS REAL)) AS drawer_open_rate,
    AVG(CAST(json_extract(payload, '$.time_to_first_hunk_action_ms') AS REAL)) / 1000.0 AS avg_review_sec
  FROM events
  WHERE kind = 'turn_review_completed'
    AND json_extract(payload, '$.files_changed') > 0
  GROUP BY view_mode;
  ```

### Experiment 2: Challenge-Response Gate vs. Reflex `↵` Habituation (Bet #1 / S1)
- **Hypothesis (`test:`)**: Unbinding `↵` on high-risk gates and requiring a click/shortcut on the highlighted **Risk Token** (host, destructive flag, or out-of-scope path) will eliminate sub-second reflex approvals and catch seeded dangerous commands without increasing median decision time by more than 2.5 seconds.
- **Method & Sample**: $N = 5$ testers running in `Mode::Auto` over 50 sessions. Inject 4 benign escalations (e.g., `gh api` read-only with unusual flag) and 2 hazardous escalations (e.g., `curl` piped to interpreter or `git checkout --` on an edited file) during multi-turn tasks.
- **Success Criterion**:
  1. `approval_latency_ms < 600` drops to **$0\%$** (from baseline $18\text{–}35\%$).
  2. Hazardous escalations denied (`ApprovalDecision::Reject` or `Say`): **$100\%$**.
  3. Median `approval_latency_ms` stays under `3500ms`.
- **Local Ledger SQL Query (`~/.cordata/state.db`)**:
  ```sql
  SELECT
    json_extract(payload, '$.gate_style') AS gate_style,
    COUNT(*) AS total_gates,
    SUM(CASE WHEN json_extract(payload, '$.latency_ms') < 600 THEN 1 ELSE 0 END) * 100.0 / COUNT(*) AS reflex_pct,
    AVG(json_extract(payload, '$.latency_ms')) AS avg_latency_ms,
    SUM(CASE WHEN json_extract(payload, '$.reverted_within_60s') = 1 THEN 1 ELSE 0 END) AS regret_count
  FROM events
  WHERE kind = 'permission_decision'
  GROUP BY gate_style;
  ```

### Experiment 3: Checkpoint Tape Scrubber vs. Corrective Prompt Spirals (Bet #2 / I3)
- **Hypothesis (`test:`)**: When a turn's check fails (`CheckState::Failed`), giving the developer 1-click `[Fork from Turn k]` on the [`tape`](file:///Users/asierra-llm-mbp/Development/Cordata/app/crates/cordata-app/src/workspace/desk.rs#L137) reduces wasted follow-up turns and total token spend per resolved brief compared to typing corrective prompts into a polluted context window.
- **Method & Sample**: Analyze 60 real coding sessions across 2 weeks ($N = 4$ developers) where at least one turn resulted in `CheckState::Failed`.
- **Success Criterion**: Sessions using `turn_forked` reach `CheckState::Passed` in **$\ge 35\%$ fewer subsequent turns** and **$\ge 30\%$ lower input token spend** than sessions that continue appending corrective prompts after 2 consecutive failed checks.
- **Local Ledger SQL Query (`~/.cordata/state.db`)**:
  ```sql
  WITH session_stats AS (
    SELECT
      u.session_id,
      SUM(u.tokens_in) AS total_tokens_in,
      COUNT(u.id) AS total_requests,
      MAX(CASE WHEN e.kind = 'turn_forked' THEN 1 ELSE 0 END) AS used_fork
    FROM quota_usage u
    LEFT JOIN events e ON e.session_id = u.session_id
    GROUP BY u.session_id
  )
  SELECT
    used_fork,
    COUNT(*) AS sessions,
    AVG(total_requests) AS avg_requests_to_done,
    AVG(total_tokens_in) AS avg_tokens_in
  FROM session_stats
  GROUP BY used_fork;
  ```

### Experiment 4: Multi-Agent Triage Rack vs. Sidebar Tab Switching (Bet #3 / R2)
- **Hypothesis (`test:`)**: When supervising $\ge 4$ concurrent threads/waves, the **Triage Rack** + **Batch Gate** reduces mean time-to-service a blocked gate (`attention_wait_s`) and cuts redundant tab switches (`SwitchTo1..9`) per completed thread.
- **Method & Sample**: $N = 4$ testers each given a batch of 6 independent issues on a repository to run concurrently (once with today's sidebar, once with the Triage Rack).
- **Success Criterion**: Median `attention_wait_s` for background gates drops by **$\ge 50\%$**, and `unnecessary_tab_switches` (switching to a tab and leaving within 2s without acting) drops by **$\ge 70\%$**.
- **Local Ledger SQL Query (`~/.cordata/state.db`)**:
  ```sql
  SELECT
    json_extract(payload, '$.surface') AS surface,
    AVG(json_extract(payload, '$.attention_wait_ms')) / 1000.0 AS avg_gate_wait_sec,
    SUM(CASE WHEN json_extract(payload, '$.dwell_ms') < 2000 AND json_extract(payload, '$.acted') = 0 THEN 1 ELSE 0 END) ASpoll_switches
  FROM events
  WHERE kind IN ('thread_switched', 'permission_decision')
  GROUP BY surface;
  ```
